## 1. コーディングエージェント運用ルール

### 1.1 基本フロー（1タスク＝1チケット＝1検収）

1. 人間が §6 のチケット表から**依存が満たされたチケットを1件**選ぶ
2. 付録Aのテンプレートに「チケットID・本書の該当節・対象ファイル」を埋めてエージェントに投入する。**本書の該当節と対象ファイルの現状以外は渡さない**（コンテキストを絞るほど弱いモデルは安定する）
3. エージェントが実装し、指定の DoD コマンドを自分で実行して全緑まで修正する
4. 人間が DoD コマンドを**再実行して検収**し、付録Bのチェックリストを通してからコミットする（1チケット=1コミット）
5. 不一致・疑問があればエージェントは**実装せずに**付録Dの形式で質問を返す（勝手な解釈で先に進ませない）

### 1.2 エージェントに渡すコンテキストの最小構成

* 本書の該当節（§4.x など該当モジュールの節**のみ**）
* §2（グローバル規約）と §3（データ構造）— 毎回添付する固定コンテキスト
* 対象ファイルの現在の全文（新規なら「新規」と明記）
* 該当テストファイルの全文（テストは人間側の資産。§1.3 参照）
* 依存モジュールは**公開APIのシグネチャのみ**（実装本文は渡さない）

### 1.3 禁止事項（エージェント側の絶対ルール）

1. **仕様の再解釈・独自設計の禁止**：本書の擬似コード・シグネチャ・定数名をそのまま実装する。改善案があっても実装せず質問として報告する
2. **`src/ground_handling/`（公式コード）の変更禁止**。読み取り・importは可
3. **`tests/` の変更禁止**（チケットが明示的にテスト作成・修正を指示する場合のみ可）
4. **新規依存の追加禁止**：`src/packing_core/` は numpy と標準ライブラリのみ。`training/` は torch / sklearn / cma を追加可（チケットに明記された場合のみ）
5. **数値リテラルのハードコード禁止**：寸法・マージン・重み・閾値・台数はすべて `constants.py` 経由（§3.5）
6. **公式コードのコピーは L字経路判定の移植（T-016）のみ許可**。その際は出典（ファイル名・関数名）をコメントで必須記載
7. `print` デバッグ禁止（`logging` のみ）。`time.time()` 禁止（`time.monotonic()` のみ）
8. fixtures（`datasets/fixtures/`）の手動編集禁止（生成スクリプト経由のみ）

### 1.4 出力形式

* 変更はファイル全文で提出（部分diffは事故のもと）。複数ファイルの場合はファイルごとに区切る
* 末尾に必ず：変更ファイル一覧／実行したテストコマンドと結果／仕様と異なる判断をした箇所（**原則「なし」**。ある場合は付録D形式）

## 2. グローバル実装規約

### 2.1 言語・依存

* Python は評価基盤に合わせる（仮定 A3/Q3 の回答待ち。確定まで **3.10 互換構文**で書く：`match` 文禁止、`X | None` は可）
* `src/packing_core/`：**numpy＋標準ライブラリのみ**（scipy・torch・numba 禁止。提出物に入るため）
* `training/`・`scripts/`：torch / sklearn / cma / pandas 可（チケット指定時）

### 2.2 スタイル

* 全公開関数に型ヒント必須。データの受け渡しは §3 の dataclass か `np.ndarray`（shape・dtype を docstring に明記）
* docstring は1行要約＋`Args:`／`Returns:`／`Raises:`（Google style）
* 命名：`snake_case`。座標変数は必ず接尾辞で系を明示：`pos_world` / `pos_rel`（裸の `pos` 禁止）
* 純関数を基本とし、可変グローバル状態禁止。`dataclass(frozen=True)` を既定とする（可変が必要な場合のみ通常dataclass）
* ソートは必ず `key=` を明示（dict の挿入順・浮動小数の同値順に依存しない）

### 2.3 数値規約

* 単位は m / kg / s に統一。度・cm・mm を内部で使わない（定数定義時にコメントで換算を書くのは可）
* 内部計算は float64、**エージェント出力（`place_pos`）のみ float32**（§3.4 の `make_action` が唯一の変換点）
* 幾何比較の許容誤差は `constants.EPS_GEOM = 1e-9`（同一判定）と `constants.TOL_CONTACT = 5e-3`（接触判定 5mm）の2種のみ。関数ローカルに独自 eps を定義しない
* 乱数は `np.random.default_rng(seed)` を引数注入。モジュール内で `np.random.seed` を呼ばない

### 2.4 例外・ログ・時間

* `packing_core` 内の関数は「不正入力→`ValueError`」を投げてよい。**ただし `agent.py` の `policy()` は例外を外に漏らさない**（watchdog が全捕捉、§4.12）
* ログは `logging.getLogger("packing")` 配下。1ステップの計測値は telemetry（§4.13）に集約し、ログには要約のみ
* 時間計測は `time.monotonic()`。締切は `StepBudget`（§4.11）経由でのみ扱う

## 3. 共通データ構造と座標規約（毎タスク添付する固定仕様）

### 3.1 座標系

* Z-up 右手系。X=幅、Y=奥行、Z=高さ。**開口部は Y マイナス側**（荷物は y が小さい側から入る。奥＝y が大きい側）
* コンテナ i の原点の世界座標は `origin_world(i) = (offset_x_i, 0, 0)`、`offset_x_i = i * spacing`（`spacing` は `init_states` から取得）
* 変換（`state.py` に集約。他モジュールでの直書き禁止）：

  * `pos_rel = pos_world - origin_world(i)`
  * `pos_world = pos_rel + origin_world(i)`
* `place_pos` は**荷物の中心**のコンテナ相対座標（仮定 A10：`packed_items` の `pos` も幾何中心。Phase 0 で要確認）

### 3.2 orientation テーブル（仮説→T-003 で公式実装と突合）

入力寸法を `(L, W, H)` とし、`oriented_size(size, o)` は以下を返す。**この表は README 記述からの導出仮説（仮定 A13）**。T-003 の突合で不一致が出たら、本表を修正してから実装を直す。

| o | 意味        | 返り値       | 例 size=(0.5, 0.4, 0.3) |
| - | --------- | --------- | ---------------------- |
| 0 | そのまま      | (L, W, H) | (0.5, 0.4, 0.3)        |
| 1 | X軸90°     | (L, H, W) | (0.5, 0.3, 0.4)        |
| 2 | Y軸90°     | (H, W, L) | (0.3, 0.4, 0.5)        |
| 3 | Z軸90°     | (W, L, H) | (0.4, 0.5, 0.3)        |
| 4 | Y90°→Z90° | (W, H, L) | (0.4, 0.3, 0.5)        |
| 5 | X90°→Z90° | (H, L, W) | (0.3, 0.5, 0.4)        |

## 4. モジュール別詳細仕様（`src/packing_core/`）

各節は「目的／公開API／アルゴリズム／性能予算／エッジケース／テスト」で構成。エージェントには**該当節のみ**を渡す。

### 4.1 `geometry.py` — 幾何プリミティブ（T-003〜T-005）

**目的**：回転・AABB・交差・スイープの純関数群。状態を持たない。

**公開API**

```python
def oriented_size(size: Vec3, orientation: int) -> Vec3
    # §3.2 の表。orientation not in 0..5 → ValueError

def aabb_from_center(center: Vec3, osize: Vec3) -> tuple[Vec3, Vec3]
    # (center - osize/2, center + osize/2)

def aabb_intersects(amin, amax, bmin, bmax, tol: float = 0.0) -> bool
    # 全軸で amin < bmax - tol かつ bmin < amax - tol（面接触は交差でない）

                  margin: float = 0.0) -> bool
    # inner が outer を margin 分だけ縮めた箱に収まるか（margin<0 は拡大＝緩和）

def quat_to_matrix(q: np.ndarray) -> np.ndarray

    # R = [[1-2(y²+z²), 2(xy-zw),   2(xz+yw)],
    #      [2(xy+zw),   1-2(x²+z²), 2(yz-xw)],

    # 実装時は事前に q を正規化する
```

**性能予算**：全関数 1回あたり <10µs（ベクトル化必須、Pythonループ禁止。8頂点は shape (8,3) の行列積1回で処理）。

**エッジケース**：ゼロ寸法・負寸法は ValueError。`aabb_intersects` は面がぴったり接する場合 False（tol=0 のとき厳密比較 `<` を使用）。

**テスト（`tests/test_geometry.py` に実装済み想定の期待値）**

* `oriented_size((0.5,0.4,0.3), o)` が §3.2 の例の列と一致（o=0..5）
* 恒等クォータニオン (0,0,0,1) で `rotated_aabb` = `aabb_from_center`
* Z90° クォータニオン (0,0,0.7071068,0.7071068) で size=(0.5,0.4,0.3) → AABB寸法 (0.4,0.5,0.3)（許容 1e-6）
* 面接触ケース：[0,1]³ と [1,2]×[0,1]² → `aabb_intersects` False

### 4.2 `container_space.py` — 有効空間と格子（T-006〜T-008）

**目的**：`container_list[i]` の辞書1件から、非直方体の有効空間（連続幾何）と絞り込み用格子を構築する。

**公開API**

```python
@dataclass
class ContainerSpace:
    index: int
    offset_x: float
    inner_min_rel: Vec3      # cdict["points"]/["n_vecs"]（外向き法線の半空間）から復元した内壁
    inner_max_rel: Vec3
    cut_planes: list         # 下部欠き込み等：半空間 (normal_rel: Vec3, d: float) のリスト
                             #   有効空間 = 内壁AABB ∩ {x | normal·x <= d for all}
    shelf_boxes: list[tuple[Vec3, Vec3]]  # 棚＝障害物AABB（相対）
    cell: float              # GridParams.cell
    floor_z: np.ndarray      # shape (nx, ny)。欠き込みで持ち上がった床
    ceil_z: np.ndarray       # 天井（棚下面を含む）
    height: np.ndarray       # 現在の積み上げ上端（bake_placed で更新）

def build_container_space(cdict: dict, index: int, spacing: float,
                          cell: float) -> ContainerSpace
def contains_oriented_box(space, center_rel, osize, margin) -> bool
    # 連続判定：AABB内壁チェック ＋ 全 cut_planes 半空間チェック（8頂点）
    #           ＋ shelf_boxes と非交差
def effective_volume(space) -> float      # モンテカルロ不可。格子積分（cell³）で近似し、
                                          # floor_z/ceil_z 単一区間格子上の近似・診断用体積を返す
                                          # （fillスコアの正式分母ではない）。
                                          # docstring に「fill分母はevaluator移植値を正とする」と明記
def bake_placed(space, placed: list[PlacedItem]) -> None
    # height を全再構築（回転後AABBを格子に焼き込み）。増分版は cache_* 接頭辞で別関数
def cells_of_aabb(space, bmin, bmax) -> tuple[slice, slice]
```

**アルゴリズム要点**

* `cdict` のキー名（`cut_x`/`cut_y`/棚/`thickness`/`n_vecs`/`points`/`center`/`volume`）は `interface_notes.md` の転記表（＝`constants.OBS_KEYS["container"]`）に従う。**キー名をこの仕様書から推測しない**（T-006 投入時に転記表を添付する）
* **`buffer` は `cdict` に存在しないキー**（`Container.buffer` はconfigで上書き可能な内部属性であり、observation には転記されない。T-006 で確認済み、`interface_notes.md` §I-7 参照）。固定値で補ってはならない。必要な場合は公式実装の関係式
  `buffer = float(cdict["center"][2]) - float(cdict["height"]) / 2.0` から都度復元する。
* コンテナの内壁形状（`inner_min_rel`/`inner_max_rel`/`cut_planes`）は、`thickness`/`buffer` からの寸法式で再構築するのではなく、公式包含判定と同じ `cdict["points"]`（世界座標の代表点）と `cdict["n_vecs"]`（外向き単位法線）を正として復元する：

  ```python
  origin_world = np.array([index * spacing, 0.0, 0.0], dtype=np.float64)
  point_rel = np.asarray(point_world, dtype=np.float64) - origin_world
  normal_rel = np.asarray(normal_world, dtype=np.float64)
  d = np.dot(normal_rel, point_rel)
  # 有効空間の半空間: normal_rel · x <= d
  ```

  cut なし（軸整列面のみ）の場合、6面の半空間から `inner_min_rel`/`inner_max_rel` がそのまま定まり、`cut_planes = []` となる。
* `floor_z[i,j]`：セル中心 (x,y) で cut_planes を z について解いた床高さの max。`ceil_z` は内壁上面と棚下面の min
* 格子は**絞り込み・支持率・height 用**。包含・非重複の最終判定に使わない（§2規約）
* `effective_volume(space)` は格子積分（cell³ 近似）で実装する。**責務は `floor_z`/`ceil_z` による
  単一区間格子表現上の近似・診断用体積を返すことであり、公式fillスコアの分母ではない**（正式な
  fill分母は `evaluator.py` または転記済みの公式値を正とする）。`cdict["volume"]`をそのまま返しては
  ならない。DoDの詳細（直方体基準ケースと cut・棚ケースの扱いの違い）は下記T-007節を参照。

**T-007：cut・棚の変換規則**（読解一次情報・詳細式は `interface_notes.md` §K）

* `cut_planes` の floor_z/ceil_z への反映：セル中心 `(x_c,y_c)` に対し各平面 `(normal_rel=(nx,ny,nz), d)` を
  `normal·(x_c,y_c,z) <= d` について `z` で解く。`nz < -EPS_GEOM` なら下限 `z >= (d-nx*x_c-ny*y_c)/nz` を
  `floor_z` 候補（`inner_min_rel[2]` と `max`）、`nz > +EPS_GEOM` なら上限を `ceil_z` 候補
  （`inner_max_rel[2]` と `min`）とする。`|nz| <= EPS_GEOM` の面は z を拘束しないため
  floor_z/ceil_z の算出には寄与させない（格子は絞り込み専用のため、この種のXY制約は
  `contains_oriented_box` の半空間判定でのみ最終判定する）。
* **セル中心座標・格子添字の規約**（T-006実装 `nx = max(1, round(size[0]/cell))` /
  `ny = max(1, round(size[1]/cell))`（`size = inner_max_rel - inner_min_rel`）をそのまま正式仕様と
  する。変更不要）：
  ```python
  x_c[i] = inner_min_rel[0] + (i + 0.5) * cell   # i = 0, ..., nx-1
  y_c[j] = inner_min_rel[1] + (j + 0.5) * cell   # j = 0, ..., ny-1
  ```
  有効index範囲は `i∈{0,...,nx-1}`, `j∈{0,...,ny-1}`。端数セル（`round()`により`nx*cell`が
  `size[0]`と厳密一致しない場合、最大`cell/2`の差）について、`effective_volume()`は全セルを
  `cell×cell`として扱い面積補正は行わない（T-006既存実装のまま）。`nx=round(size/cell)`の定義
  （`|nx-size/cell|<=0.5`）から `x_c[nx-1] <= inner_max_rel[0]` が常に成り立つため（Y軸も同様）、
  セル中心が内壁境界を超えることはなく、クランプ処理は不要（証明は `interface_notes.md` §K.7参照）。
* 小棚（`_create_small_shelf` 相当）・大棚（`_create_shelf` 相当）のAABBは、公式コードの
  `halfExtents`/`position` 式（`interface_notes.md` §K.2/K.3）をコンテナ相対座標へ変換して求める。
  **小棚は `cdict["shelf"]` の真偽・`cut_planes` の有無にかかわらず常に計算する**（公式コード上、
  `require_shelf` の分岐によらず無条件生成されるため）。**大棚は `cdict["shelf"] is True` の
  ときのみ計算する**。生成条件を `cut_planes` の有無で判定してはならない（`cut_planes` は
  半空間分類上の非軸整列面リストに過ぎず、cut形状の存在を表す正式なフラグではないため）。
* 算出したAABBは `inner_min_rel`/`inner_max_rel` で軸ごとにクリップ（`elementwise_max`/`min`）した上で、
  クリップ後の全軸長が `EPS_GEOM` を超える場合のみ `shelf_boxes` に追加する（ゼロ・負寸法は追加しない）。
  クリップが必要な理由：大棚のX半径 `length/2-thickness/2` は内壁AABBのX境界より壁厚半分だけ外側に
  出るため（`interface_notes.md` §K.4）。
* `contains_oriented_box` は上記に加え、cut・棚を含む拡張として (1) 内壁AABBチェック、
  (2) 箱の8頂点すべてが全 `cut_planes` の半空間を満たすことの確認、(3) 箱AABBが `shelf_boxes` の
  いずれとも交差しないことの確認、を行う。
* 既存 `tests/test_container_space.py` の合成fixtureは `cut_x=0.3`/`cut_y=0.3` を保持したまま
  cutなし直方体を意図しており、上記の小棚無条件生成則と矛盾する。この矛盾は fixture 側の
  不整合として扱い、T-007のテスト準備セッションで `cut_x=0.0, cut_y=0.0` に修正する
  （`container_space.py` にfixture救済分岐は追加しない。`interface_notes.md` §K.5）。
* golden fixture は `ground_handling/utils.py::write_open_cut_corner_cup_obj`（PyBullet非依存の
  純関数）を固定パラメータで直接呼び出して `points`/`n_vecs` を取得し、期待 `floor_z`/`ceil_z`/
  shelf AABB は `container_space.py` を経由しない独立計算で求める（`interface_notes.md` §K.9）。
* `effective_volume(space)` の責務とDoD（cut・棚を含む場合の扱いを再定義。実測調査の結果、
  棚上方空間の喪失により `cdict["volume"]` との<1%一致は構造的に達成不可能と判明したため）：
  - **責務**: `floor_z`/`ceil_z` による単一区間格子表現上の近似・診断用体積を返す関数と位置づける。
    公式fillスコアの分母には使用しない。fill分母は `evaluator.py`（または転記済みの公式値）を
    正とする、既存の docstring 方針（本節冒頭）を維持・強化する。
  - **DoD①（直方体基準ケース）**: `cut_x=0`・`cut_y=0`・小棚がクリップ後ゼロ体積・`shelf=False`・
    `cut_planes` なしの場合、解析的な内壁体積との相対誤差 <1% を維持する。
  - **DoD②（cut・棚を含むケース）**: `cdict["volume"]` との一致は求めない。golden の
    `floor_z`/`ceil_z` から独立計算した格子積分値
    （`sum(max(ceil_z-floor_z, 0) * cell * cell)`。全セルを `cell × cell` として扱う現行実装の
    仕様に合わせ、境界セルの特別扱いはしない）と一致することを検証する。比較は
    `np.testing.assert_allclose(actual, expected, rtol=0.0, atol=EPS_GEOM)` を原則とする。
    浮動小数演算順序により `EPS_GEOM` で不安定な場合は、恣意的に許容値を広げず実測値を報告して
    停止する。
  - **DoD③（公式体積との差、診断値）**: `effective_volume` と `cdict["volume"]` の絶対差・相対差は
    テスト出力またはコメントに記録するが、合否条件にはしない。
  - **既知の近似誤差**（本チケットで実測済み。固定fixture: `length=height=width=1.00`,
    `thickness=0.02`, `cut_x=cut_y=0.20`, `buffer=0.02`, `shelf=False`。詳細は
    `interface_notes.md` §K.10）：
    - cut床上昇のみ反映: 対公式体積式で相対誤差 約2.37%
    - cut床上昇＋小棚ceilキャップ反映: 対公式体積式で相対誤差 約8.28%
    - 棚ceilキャップによる上方空間の喪失体積: 約0.09216 m³（公式体積の約10.65%）
    これらは記録用の実測値であり、**本番コード（`container_space.py`）へ数値としてハードコード
    しない**。
  - **`effective_volume()` の docstring に明記する事項**（実装セッションで反映）：
    1. 格子表現（`floor_z`/`ceil_z`の単一区間）上の近似体積であること
    2. 棚のあるセルでは `ceil_z` を棚下面に設定するため、棚上方空間を保守的に無視すること
    3. cut形状では、格子離散化と公式体積式の形状定義差（`interface_notes.md` §K.10）により
       誤差が生じること
    4. fillスコアの分母には使用しないこと。fill分母は `evaluator` 由来の公式値を正とすること
    5. 包含の最終判定は `contains_oriented_box()` の連続幾何を使用すること
  - **既知の制約（スコープ外）**: 棚上方空間を単一区間の `floor_z`/`ceil_z` で表現できない点は、
    T-007では対応しない。複数区間・バンド表現への拡張は将来的な改善候補とし、T-007/T-008の
    スコープには含めない（棚体積のみを別経路で減算する方式も、`floor_z`/`ceil_z`とは異なる
    空間モデルの二重化を避けるため今回は採用しない）。

**性能予算**：`build` <50ms/台、`bake_placed`（80個）<80ms/台。

**テスト**

* 直方体のみ（`cut_x=0`・`cut_y=0`・`shelf=False`、cut_planesなし）：

* cut あり fixture（`write_open_cut_corner_cup_obj` を固定パラメータで直接呼び出して生成、

**T-008：`cells_of_aabb`・`bake_placed` の変換規則**

* **セル帰属規約（半開区間・セル中心代表）**：格子中心座標は `_build_floor_ceil`（T-006/T-007）と
  完全に同じ生成式を使う（別の座標計算規約を新設しない）。

  ```python
  x_center[i] = space.inner_min_rel[0] + (i + 0.5) * space.cell   # i = 0, ..., nx-1
  y_center[j] = space.inner_min_rel[1] + (j + 0.5) * space.cell   # j = 0, ..., ny-1
  ```

  AABB（`bmin`, `bmax`）の各軸について、セル中心が次の半開区間に入るセルを選択する。

  ```text
  bmin <= cell_center < bmax   # 下端は含む、上端は含まない
  ```

  したがって、2つのAABBが同一平面で面接触し、その境界がちょうどセル中心と一致する場合、
  境界セルは上側（`bmax`側）のAABBにのみ帰属し、下側（`bmin`側）のAABBには帰属しない
  （重複帰属しない）。NumPy実装では、格子中心列に対する `np.searchsorted` と等価にする。

  ```python
  start = np.searchsorted(centers, clipped_min, side="left")
  stop = np.searchsorted(centers, clipped_max, side="left")
  ```

* **clamp規約**：まずXY範囲をコンテナ内壁のXY範囲と交差させる。

  ```python
  clipped_min = np.maximum(bmin[:2], space.inner_min_rel[:2])
  clipped_max = np.minimum(bmax[:2], space.inner_max_rel[:2])
  ```

  インデックスは最終的に `X: [0, space.height.shape[0]]`・`Y: [0, space.height.shape[1]]` の
  範囲へ収める。`EPS_GEOM` によるセル占有範囲の外側拡張は行わない。

  入力検証：`bmin`/`bmax` は shape `(3,)`・全要素有限値であることを要求し、いずれかの軸で
  `bmax < bmin - EPS_GEOM` となる場合は `ValueError` とする。clamp後にXY面積が正でない場合は
  空範囲（後述）を返す。

* **空範囲の表現**：AABBがコンテナXY領域と交差しない、またはclamp後に正のXY面積を持たない場合は、
  必ず次のcanonical形を返す（片方の軸だけ実範囲を残した空sliceにしない）。

  ```python
  (slice(0, 0), slice(0, 0))
  ```

* **`bake_placed(space, placed: list[PlacedItem]) -> None`**：呼び出しのたびに `height` を
  全再構築する（前回の `height` を引き継がない。増分キャッシュは実装しない）。

  1. `space.height[...] = space.floor_z` で初期化する（各セルの有効床高さ）。
  2. 各 `PlacedItem` について、`aabb_min_rel`/`aabb_max_rel` をそのまま（回転AABBの再計算はせず）
     `cells_of_aabb` へ渡す。
  3. 返り値が空slice（`(slice(0,0), slice(0,0))`）ならその荷物をスキップする。
  4. 対象セルを次で更新する（現在値と `aabb_max_rel[2]` の max を保持。`ceil_z` によるclampはしない）。

     ```python
     space.height[x_slice, y_slice] = np.maximum(
         space.height[x_slice, y_slice],
         placed_item.aabb_max_rel[2],
     )
     ```

  5. `floor_z`/`ceil_z` は変更しない。

* **性能予算**：`bake_placed`（80個）<80ms/台（既存記載を維持）。

* **T-008テスト**（`tests/test_container_space.py` へ追記想定。以下の観点を最低限含める）：

  1. 空の `placed` で `height == floor_z`
  2. 1個のAABBが想定したセル中心範囲だけを更新する
  3. 上端境界（`bmax`）がセル中心と一致した場合、そのセルを含まない
  4. 下端境界（`bmin`）がセル中心と一致した場合、そのセルを含む
  5. 内壁外へ一部はみ出すAABBがclampされる
  6. 完全に範囲外のAABBがcanonicalな空slice（`(slice(0,0), slice(0,0))`）を返す
  7. 複数AABBが同じセルを覆う場合、最大の top-z を保持する
  8. 同じ `placed` で2回 `bake_placed` を呼んでも同じ結果になる（べき等性）
  9. 2回目の呼び出しで荷物を減らすと、古い `height` が残らない（全再構築の確認）
  10. `bake_placed` 呼び出し前後で `floor_z`/`ceil_z` が変更されない
  11. 80個の `PlacedItem` で性能予算（<80ms/台）を満たす

### 4.6 `stability.py` — 幾何安定性プロキシ（T-020〜T-021）

**公開API**

```python
def support_ratio(state, cand) -> float
    # 底面セル（cells_of_aabb）のうち、height[i,j] >= cand底面z - TOL_CONTACT
    # を満たすセル面積比。床（floor_z）支持も同条件で含む。0..1
def support_polygon(state, cand) -> np.ndarray   # shape (K,2)
    # 支持セル中心点の凸包（Andrew monotone chain を numpy で実装。scipy 禁止）
def cg_margin(state, cand) -> float
    # 荷物中心 (x,y) から凸包境界までの符号付き距離（内側+／外側−）。
    # K<3（点・線支持）のときは -inf 扱い（=不安定）
def max_step_below(state, cand) -> float          # 底面下の height の最大段差
def soft_below_ratio(state, cand) -> float        # 支持セルのうちソフト荷物上面の比率
```

**monotone chain 擬似コード**（実装指示）：点集合を (x,y) 辞書順ソート→下側凸包→上側凸包→連結。同一点は事前に `np.unique`。

**テスト**

* 平床に置く → support_ratio=1.0、cg_margin = min(osize.x, osize.y)/2（正方支持なら辺長/2、許容 1e-3）
* 0.4×0.4 底面の半分が 0.2 幅の台に載る → support_ratio ≈ 0.5、CG は台の縁上 → cg_margin ≈ 0.0（|値|<1cm）
* 2点支持（K=2）→ cg_margin = -inf

### 4.8 `score.py` — スコアと期待値・レジーム（T-025, T-036）

```python
def heuristic_score(state, cand, sp: ScoreParams) -> float
    # DBLF基本 + ボーナス（すべて [0,1] 正規化した項の線形結合、重みは ScoreParams）:
    # s = - sp.w_z * z_top_norm            # 低く
    #     + sp.w_y * y_center_norm         # 奥（+Y）へ
    #     - sp.w_x * x_center_norm         # X 若い側へ
    #     + sp.w_support * support_ratio
    #     - sp.w_cg_h * cg_height_norm     # 重量物ほど低く: weight_norm を乗じる
    #     - sp.w_soft * hard_on_soft_flag  # ソフト上ハードのペナルティ
    #     + sp.w_prio * priority_ok_flag   # 優先荷物が優先コンテナ/上側
def regime(state, rp: RegimeParams) -> str
    # placed総数 < rp.regime_threshold_n → "conservative" else "aggressive"
def effective_score(score: float, p_ng: float, mode: str, rp) -> float
    # p = 1 - p_ng
    # conservative: (p ** rp.gamma_cons) * (1 + score)   # gamma_cons=4.0 初期値
    # aggressive:   (p ** rp.gamma_aggr) * (1 + score)   # gamma_aggr=1.0
    # score は [-3,3] 想定のため 1+score>0 を assert
```

初期重み（`ScoreParams` 既定）：w_z=1.0, w_y=0.3, w_x=0.1, w_support=0.5, w_cg_h=0.3, w_soft=0.8, w_prio=0.4。Phase 4 でローカル evaluator により較正（数値変更は constants のみ）。

**テスト**：平床の2候補（低い vs 高い）で低い方が高スコア／conservative で p_ng=0.3 と 0.05 の候補が逆転すること（score 差 0.2 以内の設定で）。

## 7. Phase 5 以降の実装指針（モジュールレベル）

弱いエージェントに任せるのは**枠組みとテストが確定した部分のみ**。ハイパーパラメータ・ネット構造は設計書 §6/§9 の数値をそのまま使い、エージェントに選ばせない。

### 7.1 `training/env_wrapper.py`（T-040）

* `compute_potentials(state) -> dict[str, float]`：evaluator 移植式で fill/cog/stability_proxy/placement/soft の各ポテンシャル Φ_k を算出
* 報酬 `r_t = Σ_k w_k (Φ_k(s_t+1) − Φ_k(s_t))`、終端で公式スコアを加算。NG 終了は「以後のポテンシャル獲得を失う」ことで自然に罰となる（追加の死亡ペナルティ定数を勝手に足さない）

### 7.2 `training/fast_env.py`（T-041）

* 契約：observation の辞書スキーマは公式と同一キー（interface_notes の転記表）。物理なし（置いた位置に確定）
* 一致テスト：ランダム 20 エピソードで、各ステップ後の height を公式 env と比較（許容＝cell 相当。物理沈降差はテスト用に「軽量・低摩擦アイテムのみの config」で抑える）

### 7.3 `training/adversary.py` v0（T-042）

```
初期集団: 課題パラメータ θ を M=16 サンプル
反復: 各 θ で公式envを E=3 エピソード実行 →
      目的 J(θ) = 10 * NG率 + mean(参照解スコア − 現行スコア)
      上位 k=4 を残し、連続値はガウス摂動・カテゴリ値は再サンプルで補充
出力: 上位課題を datasets/adversarial/gen_<n>/ に config JSON として保存
```

* 参照解＝その時点の最良ヒューリスティック。CMA-ES 化はランダム探索で効果確認後（別チケット）

### 7.4 推論3形式（Phase 6、T-043 以降で追補）

* `model.pt`（TorchScript）／`model.onnx`／`model_weights.npz`（numpy 前向き）の3形式を同一入力で突合するテスト（onnx: atol 1e-4、npz: 1e-6）を必須とする
